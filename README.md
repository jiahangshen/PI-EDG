# PI-EDG

**Physics-Informed Full-Space Electron Density Generation from Molecular Geometry**

This repository contains the voxel-based PI-EDG implementation associated with
the manuscript of the same name. Given a neutral molecule's atomic numbers and
coordinates, PI-EDG predicts a full-space electron-density field on a `64³`
grid. It does not require a density-derived input at inference time.

> **Release scope.** This is a source-code release of the paper's voxel model,
> not a pretrained model or a turnkey reproduction of every reported table.
> Please read [Paper–implementation alignment](PAPER_ALIGNMENT.md) before
> comparing numerical results with the manuscript.

## Method at a glance

```text
Molecular geometry
    ├─ element-resolved atom grid + position encoding
    └─ nuclear external-potential field
          ↓
PhysicsResUNet with a hybrid FNO–CNN bottleneck
          ↓
Density-space MoE: log-density routing, 37 experts, soft fusion
          ↓
Raw 64³ electron density
          ↓  optional inference-time neutral-electron scaling
Normalized 64³ electron density
```

The network uses a cube-root density target during training to span the large
density range. Electron-number scaling is applied **after inference** in the
paper-method command below; the training-time hard constraint and hard routing
remain disabled. The base model contains **50,661,546 parameters**.

The manuscript reports the following results on EDBench. These are *paper
values*, not measurements regenerated by the commands in this repository:

| Paper-reported measure | Value |
| --- | ---: |
| Density MAE under the manuscript's stated output protocol | `3.405 × 10⁻³` |
| Mean inference time per molecule | `133.4 ms` |
| External-region molecular electrostatic-potential MAE | `5.300 × 10⁻² Hartree/e` |

The exact evaluation protocol and paper/code differences matter; see
[PAPER_ALIGNMENT.md](PAPER_ALIGNMENT.md).

## Installation

The manuscript records Python `3.8.20`, PyTorch `2.4.1+cu121`, and CUDA
`12.1`. Use a PyTorch build compatible with your GPU, then install the
remaining dependencies:

```bash
python -m pip install -r requirements.txt
```

Other versions may work, but have not been validated against the manuscript's
results. The optional `--optimizer_type adafactor` switch additionally needs
`transformers`; the example below uses AdamW.

## Data preparation

Download EDBench SDF/CUBE files from the original data provider. This
repository does **not** redistribute EDBench, DFT density grids, model weights,
or third-party baseline implementations. The preprocessing script expects one
numeric directory per molecule, each containing one `.sdf` and one single-field
`.cube`; nested shard directories are supported:

```text
/path/to/edbench/raw/
└── shard_000/
    └── 19412/
        ├── geometry.sdf
        └── density.cube
```

Build the cache once:

```bash
python preprocess_cache.py \
  --raw_data_root /path/to/edbench/raw \
  --cache_dir /path/to/edbench/cache \
  --recursive_sample_scan \
  --cache_format train_ready_grid64
```

The cache contains the historical hard-binned `64³` density target and
centered atom coordinates. Its filenames use the numeric molecule IDs in
[`splits/`](splits/), regardless of the enclosing shard name. Duplicate IDs
or malformed samples cause preprocessing to fail rather than silently shrink
the dataset. `legacy_points` is available for the older point-list workflow.

## Training

The frozen ID files contain **18,689 training** and **2,076 validation**
molecules. For a single-GPU run using the manuscript's tabulated learning
rate and 30-epoch horizon:

```bash
python train_softmoe_phys_duoka.py \
  --devices 0 \
  --raw_data_root /path/to/edbench/raw \
  --cache_dir /path/to/edbench/cache \
  --train_id_file splits/train_ids.npy \
  --val_id_file splits/validation_ids.npy \
  --strict_data --bins_mode decade_exact \
  --model_scale base --batch_size 8 --max_epochs 30 \
  --learning_rate 1e-5 --threshold_lr_scale 0.1 \
  --lambda_global 1 --lambda_guide 1e-5 \
  --constraint_start_epoch -1 --hard_routing_epoch -1 \
  --skip_lr_find --logger_type csv
```

`--batch_size` is per GPU. A recorded reviewer run instead used learning rate
`1e-4`, stopped after 12 epochs, and set
`--routing_backbone_grad_scale 0.3`; the two configurations must not be
presented as identical. See the [alignment audit](PAPER_ALIGNMENT.md) for the
other known differences.

## Predict and evaluate

After training, use a Lightning checkpoint from `checkpoints_hybrid/` to
predict from a neutral SDF or XYZ geometry:

```bash
python predict.py \
  --checkpoint /path/to/best.ckpt \
  --structure /path/to/molecule.sdf \
  --output outputs/molecule.npz \
  --voxel-volume-bohr3 0.064
```

The `.npz` contains `raw_density_zyx`, `normalized_density_zyx`, atomic
numbers, and the coordinate-centering metadata. The normalized prediction is

```text
ρ′ᵢ = Nₑ max(ρᵢ, 0) / (Σⱼ max(ρⱼ, 0) ΔV + 10⁻⁸),   Nₑ = Σₐ Zₐ.
```

The voxel volume must match the density cache's integration convention.
`0.064 Bohr³` corresponds to a `0.4 Bohr` source-CUBE step; it is **not** the
geometric voxel volume of the displayed `64³` box.

To evaluate a frozen ID list against cached, unnormalized DFT grids:

```bash
python evaluate.py \
  --checkpoint /path/to/best.ckpt \
  --cache-dir /path/to/edbench/cache \
  --sample-ids splits/reported_2000_ids.txt \
  --output-dir outputs/evaluation \
  --voxel-volume-bohr3 0.064
```

This writes `per_molecule.csv` and `summary.json` with raw and normalized
MAE/RMSE/Pearson and electron-number errors. The 2,000 reported IDs are a
**subset of the 2,076 validation IDs**, not an independent held-out test set;
see [`splits/provenance.json`](splits/provenance.json). Do not use this subset
to claim an independent test result.

Run the included checks with `python -m unittest discover -s tests`. They
verify core release invariants, but do not replace a full training or
paper-table reproduction. No checkpoint is supplied, and the manuscript/code
differences are documented in [PAPER_ALIGNMENT.md](PAPER_ALIGNMENT.md).
